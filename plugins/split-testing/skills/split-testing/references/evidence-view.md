# Evidence View

Load this route only after evidence exists and only when the user requests a visual result or a persistent visual projection would materially improve inspection, communication, or reuse. No view is required merely because the evidence is complex, preserves several distinctions, or can be plotted.

An evidence view is a derived, non-authoritative projection of already-retained evidence. The evidence and live decision remain authoritative. The orchestrator chooses the representation, transformations, interactions, and available tools for the actual evidence and intended consumer. Do not begin from a chart catalog, visual grammar, renderer taxonomy, favored library, dashboard convention, or standard gallery.

A view cannot decide what should have been observed, add or remove evidence, authorize aggregation, supply utility or weights, select a winner, convert diagnostic evidence into prevalence, or strengthen the underlying inference. Keep source references and derivations traceable, expose consequential filtering or transformation, and preserve vetoes, genuine non-dominance, uncertainty, and missingness when they affect interpretation.

If presentation itself can change the consumer's action, treat the view as an observation instrument and test the decision-relevant presentation effect. Do not let visual salience silently become evidence weight.

A pattern first discovered through a post-result view remains exploratory unless the existing analysis prospectively authorized that inference. If the pattern could change the action, reopen a prospective analysis or observation round. Do not retroactively redefine inclusion, outcomes, populations, or stopping around the visible pattern.

Match the view to its consumer and purpose. The same evidence may legitimately need different projections for inspection, explanation, accessibility, or reuse, and the simplest adequate projection may be best. Visual sophistication, interactivity, panel count, and represented-variable count are not evidence quality.

Ephemeral conversational visuals need no package. For a durable view, retain source references, entry points, derivation and runtime references when applicable, external dependencies, and interpretive disclosures. The delivered reader should expose package identity, retained provenance, raw evidence access, and declared dependencies as technical inspection surfaces, not as semantic summaries or judgments. Pin an environment only when regeneration is claimed, and verify regeneration and the delivered consumer boundary there. The optional derived-view helper seals and verifies package integrity; its reader is a technical shell that packages authored entrypoints and raw references, not a semantic renderer. It does not decide what the view means, whether it is persuasive, or whether it is appropriate.
