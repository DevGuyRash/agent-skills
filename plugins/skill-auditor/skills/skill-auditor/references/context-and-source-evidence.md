# Context and Source Evidence

Measure context at the host boundary that actually loads it and connect the observation to a named
decision or execution trajectory. Include passive metadata, tool schemas, injected repository
instructions, and condition-specific prompts when consequential. Total package size, file count, and
prompt length are weak proxies: smaller context can cause wandering, while relevant guidance can
prevent a material omission. A context repair needs behavioral evidence on the affected model, host,
and task population rather than a universal threshold.

Keep essential execution guidance locally sufficient. External documentation supplies authority,
current evidence, or optional depth rather than becoming an undeclared runtime dependency. Organize
local references around decisions that can be made independently; add an index, table of contents, or
split only when navigation materially improves. Do not infer a navigation defect from a line count.

Prefer official primary authority and verify that the cited page supports the consequential claim.
Choose a source horizon deliberately:

- a canonical rolling link for instructions intended to follow current stable policy or behavior;
- an immutable version or commit permalink for reproducibility, historical claims, exact
  compatibility, or fixed-release behavior;
- a supported release-family link when the contract intentionally follows that line; and
- a moving development source only when movement is intended and clearly identified.

Record the exact consulted revision in retained evaluation evidence when reproducibility matters,
even when the instruction appropriately uses a rolling canonical link. Treat redirects, missing
anchors, authentication, and unavailable sources as observations requiring interpretation. Retain a
reopening condition when an upstream change could invalidate the conclusion.
