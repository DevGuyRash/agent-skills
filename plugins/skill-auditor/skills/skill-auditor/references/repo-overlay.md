# Repository Overlay

## Repository skill-quality authority

For every Agent Skill and plugin governed by this repository, `skill-auditor` is the final judge of applicability, materiality, quality, and release disposition. A deterministic check may block only an objectively testable requirement from the adopted Agent Skills specification, a named supported-host contract for the exact distribution surface, or an explicit repository interface or behavior commitment. Physical lines, characters outside an applicable field or package limit, estimated tokens, file or reference counts, and aggregate catalog size are review signals only; token counts are blocking only when the governing authority names the tokenizer or the host reports the count. Preserve substantive instructions and behavior unless evidence establishes a material defect. Local contracts and validators SHALL mirror this authority and SHALL NOT create independent quality limits.

Use the ambient `AGENTS.md` files that govern the audited path as sources for concrete repository commitments. The repository skill-quality authority above governs how those commitments and audit signals affect disposition; this reference does not duplicate their scope-specific rules. Do not apply this repository's preferences to an external target or present them as portable Agent Skills requirements.

For this repository, consequential package changes include dual-host publication and converter round trips, catalog and manifest parity, installed-source behavior, direct skill-root-relative resources, LF text, executable launchers, and the maintained metadata interfaces. Verify the exact current rule in `AGENTS.md` rather than treating this summary as its source.

Numeric context and file-size guidance is a signal to inspect the active path, not an independent quality verdict. Likewise, a recommended CLI, reference organization, dispatch shape, or description style needs a target-specific consequence before it becomes a finding. The governing architecture controls instruction-system design even where older repository prose presents one technique as a universal method.

When an audit depends on repository installation behavior, remember that local-source marketplaces persist and remote-tracked caches do not change until the source is pushed and reinstalled. Identify the active copy before claiming a routing repair worked.

`scripts/frontmatter_check.sh`, `scripts/reference_check.sh`, `scripts/script_sanity.sh`, and `scripts/plugin_check.sh` may expose relevant structural facts. Interpret them against the governing `AGENTS.md`, target intent, and observed behavior; do not count their observations or convert them into a house-style compliance score.
