# Executable Evidence

Use this reference when a target contains or directs a consequential executable mechanism. Judge the composed behavior the user or host will receive, not prose about the mechanism and not an atomic helper in isolation.

Establish the mechanism's authorized effects, protected state, inputs, outputs, failure meaning, and consumer horizon from target or adopted authority. Then observe whether the real mechanism preserves those distinctions. Names, parameters, schema fields, preflight checks, and separate code paths do not prove that logical roles remain distinct at runtime. When two roles carry different authority, verify that aliasing, shared backing state, replacement, indirection, or composition cannot transfer authority from one role to the other at the horizon the target promises.

For a mechanism with external effects, retain evidence of the relevant state before and after the operation and reconcile every consequential change with the authorized effect. Include reachable completion, refusal, partial failure, retry, and concurrent behavior only when they could change the repair or release decision. A successful exit is not success when the wrong object changed, a protected object disappeared, an independently promised effect was skipped, or the consumer cannot use the delivered result.

Derive probes from the target's promises and plausible operating boundary. Exercise normal behavior as a control and choose counterexamples capable of distinguishing the claimed property from a plausible but incorrect implementation. Do not bless generated output as its own oracle. A failing probe can establish a defect without proving the smallest safe repair; a passing probe establishes only the boundary it actually exercised.

Establish the authority an executable can exercise and whether information or effects can cross a boundary the package does not authorize. Inspect and run the real mechanism when safe; Markdown, tests, deterministic reporters, and static validation remain observations rather than substitutes. Unsafe or external-effect work belongs in a disposable environment or faithful simulation. Preserve an unexercised risk as unverified rather than weakening the claimed boundary.

Before calling a repair narrow, safe, or sufficient, retain evidence that distinguishes the failed property from adjacent behavior the change must preserve. Verify delivery from the working directory, package location, interpreter, permissions, inputs, and collection semantics the actual consumer supplies. Producer-workspace success does not establish that copied, installed, converted, or published artifacts resolve their declared dependencies.

When a consequential property remains unresolved after the primary audit, an independent observer can supply raw evidence without inheriting the auditor's attention path. The observer's assignment is the target-owned property and evidence boundary, not “audit this target.” Its return should make the state transition or consumer result independently checkable. The auditor remains responsible for authority, materiality, repair scope, and the final conclusion.

For a mutation-capable mechanism whose contract protects some state while authorizing other state to change, the observer establishes whether allowed caller bindings preserve that separation at runtime. State the target-owned effect boundary and ask for reproducible before/after evidence; do not name a suspected aliasing technique or implementation flaw. The observation is incomplete if it reports only the nominal destination or a successful exit while leaving the protected state unobserved.
