# ADR 0025: Centralize comparative method and keep visual views derived from evidence

- Status: Accepted
- Date: 2026-08-30

## Decision

Split Testing is the repository's single owner of generic comparative-evidence method. Skill Auditor delegates every newly needed comparison to Split Testing while retaining the audit claim, authority interpretation, materiality, severity, repair, release, and reopening. The plugins remain independently installable and declare no hard dependency. When Split Testing is unavailable, Skill Auditor may assess fit existing evidence but does not reconstruct a comparison; it emits the portable request and preserves the unresolved audit consequence.

The live decision produces its authoritative evidence basis in whatever representation fits the work. No universal evidence-record artifact, benchmark shape, result vocabulary, dimension model, or report form is required. Deterministic custody uses role-neutral commitments, work units, complete accounting, publication, reveal prerequisites, portable content integrity, and external receipts only where those hazards matter.

Visual output is an optional post-evidence projection. It cannot select observations, rewrite evidence, authorize aggregation, supply values, or decide the action. The orchestrator chooses the representation and tools for the retained evidence and intended consumer. Persistent views may use the integrity-only package and offline reader shell; conversational views need no package. A view capable of changing the consumer's action is itself an observation instrument whose presentation effect must be justified.

## Why

The previous Auditor task-value route and Split Testing manual carried substantially overlapping instructions for condition design, prompt separation, instrument validity, repetition, review, and inference. Maintaining both invited drift and divided improvement effort. A hard dependency or merged audit umbrella would have reduced portability even though comparative method remains useful outside audits and audit disposition remains meaningful without a runnable comparison.

Earlier comparison instructions also accumulated visible experimental forms that could be mistaken for the goal. The reusable property is not resemblance to a known test family or a sophisticated artifact; it is obtaining enough valid evidence to support the live action while preserving decision-changing distinctions and boundaries. Declarative instructions leave observation shape open while deterministic tools retain the few sequences whose order protects evidence.

Visual representation creates a separate post-result hazard: a view can make one aggregation or pattern appear authoritative after evidence was observed. Keeping the view derived and non-authoritative permits broad host-supported visualization without turning a renderer, library, encoding, or visual grammar into evaluation policy.

## Consequences

Split Testing 2.0 carries the decision-grounded method, caller-neutral request/result schemas, optional role-neutral custody tool, and optional derived-view package and reader. Skill Auditor 4.0 vendors the interface for standalone use and carries only its one-way routing and disposition logic, with no fallback comparison manual. Friction Diagnostics remains operationally and taxonomically separate.

Runtime instructions contain no named benchmark lineage, fixed evidence topology, fixed relationship count, required score system, visual catalog, or renderer preference. Development evaluation judges calibrated decision value, validity failures, cost, and avoidable ceremony rather than visible framework compliance. External model critique can challenge the design but is not acceptance evidence.

Reopen the separation if repeated cross-host evidence shows that optional handoff cannot preserve claim fit, if a merged package is necessary for an actual supported-host boundary, or if generic authored views repeatedly fail delivery despite retained dependencies and boundary verification. Reopen a deterministic mechanism only for a demonstrated integrity hazard; do not move semantic policy into a tool merely because it is easier to test there.
